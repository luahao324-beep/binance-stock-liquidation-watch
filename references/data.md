# 数据与可重复扫描

先通过连接器或官方公开 API 获取数据并保存来源、查询参数和获取时间。对每个标的检查合约状态；按时间分页，排序去重，校验分钟连续性。不前向填充缺失分钟，也不把历史未上市当正常零行情。

内置 scripts/scan.py 仅执行主价格规则与严重跌幅检查，不获取网络数据、不识别市场日历、不验证清算、不发送通知。调用前必须确认指定窗口属于目标休市范围。

输入 JSON：
```json
{"symbols":{"SKHYNIXUSDT":[[1792268400000,917.86,918.03,917.78,918.03,31546.7341]]}}
```
每行六字段为 UTC 开盘毫秒、open、high、low、close、quoteVolumeUSDT。不是 Binance 原始十二字段；原始成交额在索引 7，必须正确映射，不可拿基础资产数量替代。脚本要求至少 60 分钟预热。检测只用完整分钟；结束时间必须不晚于最近完整分钟的边界。

示例（路径由实际任务替换）：
```sh
python3 scripts/scan.py data.json --start 2026-10-10T04:00:00Z --end 2026-10-11T20:00:00Z --output result.json
```

窗口左闭右开，按开盘时间筛选，信号可知时间为该分钟结束。脚本检查从预热开始到窗口结束的连续数据，缺口直接失败；不静默缩小样本。默认跌幅 2%、成交倍数 5、最低成交额 100000、合并间隔 30 分钟，可用参数覆盖并在结果中保留。

主事件以首个信号触发时固定前 15 分钟收盘中位数为基准。脚本返回信号及合并事件，不内置未来收益；避免把数据不足的当前事件混入四小时回测。需要结果评估时另取至少四小时后续数据，计算逐时刻已知低点与修复，缺少观察期应标右删失，不记成未修复。

部署时额外落实：持久化事件和去重状态、断线重连及缺口标识、进程健康、交易日历与合约变更、数据过期提示、通知冷却。实时强平必须连续接收并记录；轮询 K 线无法补回遗漏的强平消息。只有用户请求持续监控时才选常驻进程或应用调度，按其已有通知授权执行。
